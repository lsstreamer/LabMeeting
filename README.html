LabMeeting 使用与写作规范

本仓库保存组会分享与项目汇报，使用 HTML / CSS / JavaScript 展示，图片、视频和简体中文字体随仓库保存。报告本身可离线打开，无需安装第三方库。

网页首页 · 各期内容简介 · 本说明的网页版本

本文件维护通用使用方法与写作约定。各期主题、内容简介、页数和报告链接统一维护在 CONTENTS.md，新增报告时持续更新；具体报告的操作和讲稿放在对应日期目录。

1. 怎么打开网页

本地直接打开

下载或复制整个 LabMeeting 文件夹，双击根目录的 index.html，从首页选择报告。也可以进入某个日期目录，双击其中的 index.html。

请保留完整目录结构：日期目录通过相对路径引用 shared/ 的主题、脚本和字体，因此只复制某个日期目录是不完整的。使用 Chrome、Edge、Firefox 或 Safari 即可，无需 npm、构建步骤或额外安装库。

说明文档可双击 README.html，各期内容简介可双击 CONTENTS.html。GitHub 上阅读对应的 .md 文件；本地浏览器阅读 .html，避免直接打开 Markdown 时显示原始文本。

在服务器上启动

服务器已有 Python 3 即可，不用进入容器。在终端运行：

bash
cd /home/sirui/workspace/LabMeeting
python3 serve.py --bind 0.0.0.0 --port 8000

保持终端运行。服务器本机浏览器访问：

text
http://localhost:8000/

首页可进入各期报告、使用说明和内容简介。serve.py 会为文本指定 UTF-8，并将 .md 自动排版成网页；查看 Markdown 原文可在地址后加 ?raw=1。

用完后，在运行服务的终端按 Ctrl+C 关闭。 若 8000 已占用，可以换成 8001，并同步修改访问地址和下面的 SSH 转发端口。

用自己的电脑访问服务器

如果可以直连服务器，将浏览器地址中的 localhost 换成服务器的 IP 或主机名。

也可以在自己电脑的终端建立 SSH 转发，将 服务器地址 替换为实际地址：

bash
ssh -N -L 8000:127.0.0.1:8000 sirui@服务器地址

保持转发终端运行，然后在自己电脑浏览器打开 http://localhost:8000/。结束时按 Ctrl+C 关闭转发。若只通过 SSH 转发访问，服务器启动命令可以使用 --bind 127.0.0.1。

2. 写作规范

以下约定面向后续维护者和 AI 助手。新增或修改报告前，先阅读本文件、CONTENTS.md、目标报告的说明与适用的 AGENTS.md，并以用户最新要求为准。

文件组织与复用

text
LabMeeting/
├── README.md / README.html        # 通用打开方法与写作规范
├── CONTENTS.md / CONTENTS.html    # 长期维护的各期内容简介
├── index.html                    # 网页报告目录
├── serve.py                      # 标准库服务器与文档生成入口
├── shared/                       # 通用主题、交互、文档排版和简体中文字体
└── YYYY_MM_DD_English_Topic/
    ├── index.html                # 本期幻灯片内容
    ├── deck.css                  # 本期排版
    ├── deck.js                   # 本期专用交互，按需提供
    ├── README.md / README.html    # 本期操作说明，按需提供
    ├── 讲稿.md / 讲稿.html        # 逐页讲解、时间安排和备查材料
    └── assets/                   # 本期原图、视频与来源记录
  • 日期目录使用 YYYY_MM_DD_英文主题，主题概括论文或项目内容，避免只用 mid、test 等模糊名称。报告类型在首页与内容简介中写清，如“论文分享”“中期报告”。
  • 公共定义放在 shared/；单篇内容与专用布局放在日期目录。修改公共样式或脚本时，检查受影响的既有功能，保留历史报告自己的实现。
  • 页面与资源使用相对路径，保留 file:// 打开能力。运行不依赖 CDN、在线字体、构建工具或需要联网加载的库；不要把服务器绝对路径或本机端口写进普通资源链接。
  • 中文明确使用简体中文字体，页面语言为 zh-Hans-CN；共用 shared/fonts/ 中的 Noto Sans SC 与许可证，不使用日文字体或日文字形版本。

内容结构与讲解

  • 按用户给定的报告时长和页数挑重点。默认沿用已认可的学术正式、清爽、有视觉变化的风格；增加实验页时同步调整讲稿用时。
  • 每个实验先说明要解决什么、输入与目标是什么、哪些参数可优化、哪些条件固定，再展示比较与结论。先介绍案例，再分析该案例的损失曲线或参数轨迹。
  • 缩写和数学符号首次出现要解释，例如 MSE、PSNR、PRDPT、RGBXY、LOIR、θ、λ、σ；不要只放名字或公式让听众自行猜测。
  • 多面板图明确标出实验名称、横纵轴、颜色对应与行列含义。生成参考帧与实际渲染结果要区分；视频帧号、优化迭代数、最终目标也要分别说明。
  • 同色点和曲线要给出对应关系，并解释为什么选择这些观察区域。例如一个区域可直接收敛，另一些区域存在错误极小值，应在图旁写明。
  • 区分论文观察、作者解释与我们的推测；不要把生成模型的一次有效输出讲成已知物理规律或必然收敛。参数是否联合更新、是否冻结，应按实际实现说明。
  • 幻灯片保持简洁、可直接讲述。复现细节和长篇解释放进讲稿或备查文档，不在画面堆放“非论文实验数据”等无助于讲解的声明。

原图、视频与来源

  • 具体案例、实验结果、定量曲线和表格使用论文或作者发布的原始材料；方法与概念讲解可以使用自制 SVG、HTML 图解。没有合适原图时，先说明情况并遵循用户选择。
  • 提取论文图片时检查完整边界、全部行列、模型名称和数字，避免截掉底部实验组。局部展示须保留可查看的完整原图；不要为了排版重画或改写实验结果。
  • 资源放在本期 assets/。来源记录使用 SOURCES.json 等清晰文件，记录作者链接、论文页码、裁剪范围等必要信息；替换图片时同步更新记录。
  • 用短图注解释图在比较什么，链接名称直接描述内容，例如“不同视频模型对比”。实验应在对应讲解页呈现；需要详细介绍的额外实验单独成页，不把一排未解释的图片链接当作讲解。
  • 论文、项目与代码入口放在首页对应报告下方；本期完整资料入口也可收录到 CONTENTS.md。原图查看器应支持完整显示与放大，视频需有播放、暂停和离页暂停。

导航、文档与更新

  • 顶部提供回到组会首页的入口，讲解全屏时隐藏工具栏。保留翻页、章节目录、全屏、图片查看等既有操作；不要把实现细节或“纯静态”等宣传字样塞进演示画面。
  • 增删页面时，同步更新静态总页数、目录、首页简介、本期说明与讲稿。共用脚本会自动生成导航页码，HTML 中的静态数字和打印输出也须正确。
  • 每次新增报告，或修改主题、页数、主要内容时，都更新 CONTENTS.md 与首页 index.html。 各期简介集中维护，通用 README 不随每一期重复增加介绍段落。
  • Markdown 是文档编辑源，HTML 是供浏览器直接打开的排版版本。修改后在仓库根目录运行下面命令，同步生成各份说明与讲稿网页：
bash
python3 serve.py --build-docs

该命令处理 README.md、CONTENTS.md 和 讲稿.md，生成各自同目录的 .html 文件；两种版本都随仓库保留。

修改与检查范围

  • 在现有用户权限下工作。必须进入容器时，参考 /home/sirui/workspace/sh/run.sh 的用户方式，不以 root 运行常规代码。
  • 仅检查本次修改直接影响的页面或功能。重点确认文字不遮挡、原图完整、资源和文档链接有效，以及新增交互能离线使用；修改通用功能时再检查相关页面。
  • 检查用的脚本、浏览器与截图放在临时目录，用完删除；为检查启动的端口及时关闭，不操作用户原有的服务。
